# Langflow integration (FR4)

The Python package `netdiag` is the engine; Langflow only orchestrates it. Custom components wrap the
shared tool registry, so adding a new tool later (speed test, port scan) means one `registry.register(...)` plus
one small component file.

| Component | Purpose | Use as |
|---|---|---|
| Network Ping Diagnostics | ping gateway + 8.8.8.8 + 1.1.1.1, deterministic diagnosis | Agent tool (Tool Mode) |
| Network Traceroute | traceroute + hop analysis | Agent tool (Tool Mode) |
| Plain-Text Network Report | LLM-free report builder | normal node |
| Groq (OpenAI-compatible) | chat model served by Groq, free-text model name | connect to the Agent's Language Model input |

## Setup

```bash
# from the repo root, in a virtualenv
pip install -e ".[langflow]"
export LANGFLOW_COMPONENTS_PATH="$(pwd)/langflow_components"
export NETDIAG_TRACE_LOG="$(pwd)/logs/agent_trace.jsonl"   # optional, this is the default
langflow run            # the startup banner prints the URL (default port 7860)
```
`netdiag` must be installed in the *same* environment as Langflow (the `pip install -e` above does that).
Open the URL printed in the startup banner; if port 7860 is busy, Langflow picks another one.

Langflow may log `Bundle 'flows' contains no Python source files`. It is harmless: the `flows/` folder
holds JSON, not components.

## Quick start: import the ready-made flow

`flows/network_diagnostic_agent.json` contains Chat Input -> Agent (ping + traceroute tools) -> Chat Output,
with the system prompt filled in and the nodes laid out left to right. It ships **without a model**, so you
add one after importing.

1. Langflow -> **Projects** -> **Upload a flow** -> choose `flows/network_diagnostic_agent.json`.
2. Add a model (see below) and connect it to the Agent.
3. Open **Playground** and send: *"Why is my internet down?"*

The file is generated by `build_flow.py` (Langflow's Graph API). Regenerate it after changing the
components or the prompt, inside the Langflow virtualenv:

```bash
python langflow_components/build_flow.py
```

## Choosing a model

**OpenAI models:** in the Agent's **Language Model** dropdown, pick a model and enter your OpenAI key.

**Groq (free tier):** Groq is not in the default model list, so use the **Groq (OpenAI-compatible)** component
in `network_diagnostics/groq_model.py`. It wraps `langchain_openai.ChatOpenAI` pointed at
`https://api.groq.com/openai/v1`.

1. Restart Langflow so it loads the component (watch the startup log for errors mentioning `GroqModelComponent`).
2. In the Agent node, open **Language Model** and click **Connect other models**. A new input appears.
3. Search `groq` in the sidebar and drag **Groq (OpenAI-compatible)** onto the canvas.
4. Enter your Groq API key (`gsk_...`). Model Name defaults to `openai/gpt-oss-120b`; any Groq model that
   supports tool calling works (`llama-3.3-70b-versatile` is a fallback).
5. On the Groq node, change the output at the bottom from **Model Response** to **Language Model**.
6. Drag from the Groq node's **Language Model** output to the Agent's **Language Model** input.

Keep keys out of git: store the key as a Langflow **Global Variable** and select it in the node, then
check any exported flow before committing:

```bash
grep -c "gsk_" langflow_components/flows/network_diagnostic_agent.json    # must print 0
```

## Build the flow by hand (about 3 minutes)

1. New flow -> add **Chat Input**, **Agent**, **Chat Output**.
2. Search "Network" in the sidebar and add **Network Ping Diagnostics** and **Network Traceroute**.
   On each, turn on **Tool Mode** and connect the *Toolset* output to the Agent's **Tools** input.
3. In the Agent: add a model (see above) and paste `agent_system_prompt.md` into **Agent Instructions**.
4. Wire Chat Input -> Agent -> Chat Output. Open the Playground and send: *"Why is my internet down?"*
5. (Optional) Export via **Export** and commit the JSON under `langflow_components/flows/`.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Imported flow shows tiny dashes with no titles | The flow JSON has no layout data. Regenerate it with the current `build_flow.py`. |
| Agent says the ping tool "isn't available" | The Agent's **Tools** input has no connection. Connect each tool node's *Toolset* output to it. |
| `attempted to call tool ... which was not in request.tools` | The model invented a tool name. Keep the prompt from naming tools by display name (the shipped prompt refers to "your ping tool"), and make sure the tools are connected. |
| `Name error ... LCModelComponent is not defined` at startup | Component files must use plain top-level imports; Langflow's loader ignores imports inside `try/except`. |
| Traceroute returns "Operation not permitted" | A local firewall rule (for example an `iptables OUTPUT DROP` used for testing) blocks the probes. The agent is told to report this and not to guess about the path. |

## Testing a fault

Block replies from one endpoint so pings fail but traceroute can still run, then remove the rule:

```bash
sudo iptables -A INPUT -s 1.1.1.1 -j DROP
# ask "Why is my internet down?" in the Playground
sudo iptables -D INPUT -s 1.1.1.1 -j DROP
```

Expected: one ping call, then a traceroute call, then a short verdict that names the unreachable endpoint.
(Blocking with `-A OUTPUT` also works for pings, but traceroute then fails with "Operation not permitted".)

## Tracing (FR5)

* Every tool call from these components is appended to `logs/agent_trace.jsonl` (tool, arguments, duration, summary).
  Override with `NETDIAG_TRACE_LOG`.
* Langflow's own Playground also shows each tool call and the Agent's reasoning steps.
